## 계산 원칙

이 수치는 작업 시간·코드 줄 수·실환경 성능의 백분율이 아니라 **아래 고정 완료 기준 20개의 충족률**입니다. 항목당 5%로 동일 가중치를 적용합니다. 난이도나 잔여 시간을 나타내는 지표는 아닙니다.

```text
개발 진행률 = (완료 기준 충족 항목 수 / 20) × 100
```

운영 코드 연결, 관련 자동 테스트 성공, 해당 변경의 main 반영을 모두 충족해야 완료로 계산합니다. 소스 작성·PR 생성·일부 CI 성공에는 부분 점수를 부여하지 않습니다.

## 기존 저장 방식의 한계

#16은 작업 실행/화면/종료 수명 기준입니다. 기존 경로 비교 writer의 파일세트 rollback은 보존하지만 모든 legacy writer를 같은 저장기로 교체하지는 않았습니다. 안전한 중간 취소가 없는 writer는 실제 반환까지 기다리고 부분 파일 가능성을 계속 안내합니다. 이를 모든 보고서의 원자적 저장·강제 취소 보장으로 확대 해석하면 안 됩니다.

## 별도 외부 검증/선행조건

- 사용자 회사 Windows 11·Aruba·PAC/WPAD·VPN·TLS 검사·GPO/EDR의 실제 검증
- 사용자 제공이 필요한 Authenticode 인증서와 실제 서명·신뢰 검증

이들은 개발 충족률과 별도로 보고할 출시 조건입니다. 개발 100%라도 실제 검증/서명이 완료되지 않았으면 그 상태를 명시합니다. 현재 작업은 새 공개 Release를 게시하지 않습니다.

## 범위 변경 규칙

기존 완료 항목을 나누어 진행률을 올리거나 새 기능을 분모에 조용히 추가하지 않습니다. 범위 변경이 필요하면 기준선 버전·추가/삭제 이유·변경 전후 수치를 함께 기록합니다. 종료 보고에는 현재 분자/분모, 새 충족 항목, 미완료 번호와 실제 배포 여부를 포함합니다.
