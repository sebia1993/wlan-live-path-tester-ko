# 개발 진행률 기준선

기준선 설정: 2026-09-07. 대상 저장소: sebia1993/wlan-live-path-tester-ko.

## 계산 원칙

이 수치는 작업 시간·코드 줄 수·실환경 성능의 백분율이 아니라 **아래 고정 완료 기준 20개의 충족률**입니다. 항목당 5%로 동일 가중치를 적용합니다. 작업 난이도나 잔여 시간을 나타내는 지표는 아닙니다.

```text
개발 진행률 = (완료 기준 충족 항목 수 / 20) × 100
```

완료로 계산하려면 운영 코드 연결, 관련 자동 테스트 성공, 해당 변경의 main 반영이 필요합니다. 소스만 작성·PR 생성·부분 CI 성공은 완료로 계산하지 않습니다. 미완료 항목에는 부분 점수를 부여하지 않습니다.

## 확인된 기준 상태와 이번 변경

- 최초 기준 main `9000c47d6601e32d1ed8353bad74029f8197239d`: 14/20 = 70%
- PR #126 반복 측정 변경: main `6a7903f1f17aeeac4826fbb93a6c0eb327f4a17d`에 병합되어 #10 충족, **15/20 = 75%**
- 이번 통합 경로 보고서 변경: #17의 코드·테스트를 작성했습니다. 정확한 최종 head에서 전체 CI 성공 후 main에 반영되면 **16/20 = 80%**입니다. 아직 CI 또는 병합 전이라면 75%를 유지합니다.

통합 보고서 저장의 공통 UI lease 연결은 #16의 일부 진전입니다. 다른 진단·보고서·자동 갱신이 남아 있으므로 #16을 완료로 계산하지 않습니다. 분모와 각 완료 기준은 바꾸지 않았습니다.

## 점수에 포함하지 않는 외부 검증/선행조건

- 사용자 회사 Windows 11·Aruba·PAC/WPAD·VPN·TLS 검사·GPO/EDR의 실제 검증
- 사용자 제공이 필요한 Authenticode 인증서와 실제 서명·신뢰 검증

이들은 개발 충족률과 별도로 보고할 출시 조건입니다. 개발 100%라도 이 외부 검증을 통과하지 않았다면 실환경 검증 또는 서명 완료라고 표현하지 않습니다.

## 범위 변경 규칙

기존 완료 항목을 잘게 나누어 진행률을 올리거나 새 기능을 분모에 조용히 추가하지 않습니다. 범위 변경이 필요하면 기준선 버전·추가/삭제 이유와 변경 전후 수치를 함께 기록합니다. 이후 작업 종료 보고에는 현재 분자/분모, 새로 충족한 항목, 미완료 번호와 실제 배포 여부를 포함합니다.
