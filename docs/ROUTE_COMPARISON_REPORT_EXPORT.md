# 경로 비교 로컬 보고서와 취소·저장 복구

이 문서는 현재 #110 코디네이터, #111 실행 Finding, #112 경로 비교 화면에 연결된 보고서 기능을 설명합니다. 보고서 생성은 이미 수집된 메모리 결과를 사용하며 DNS·라우팅·HTTP·PAC/WPAD·프록시 인증을 다시 실행하지 않습니다. AI, 외부 분석 API, 텔레메트리, 자동 업로드를 추가하지 않습니다.

## 사용 순서

1. `경로 비교`에서 승인된 내부 DIRECT 대상, 외부 HTTP(S) URL과 적용 프록시 지시문을 입력해 실행합니다.
2. `경로 보고서`의 `경로 비교 보고서 생성`을 누릅니다.
3. 필요하면 `저장 취소`를 누릅니다. 취소는 현재 로컬 파일 작업을 강제로 종료하지 않고 단계 사이에서 반영됩니다.
4. 저장 성공 시 `최신 HTML 열기`로 검토합니다. 실패·취소된 실행은 이전 성공 보고서 링크를 덮어쓰지 않습니다.
5. 외부 공유 전 JSON·CSV·HTML과 회사 정책을 다시 확인합니다.

기본 출력 위치는 `%LOCALAPPDATA%\WlanLivePathTesterKO\Reports\RouteComparison`입니다. 화면에는 전체 사용자 경로 대신 생성된 파일명만 표시합니다.

```text
WlanRouteComparison_yyyyMMdd_HHmmss.json
WlanRouteComparison_yyyyMMdd_HHmmss.csv
WlanRouteComparison_yyyyMMdd_HHmmss.html
WlanRouteComparison_yyyyMMdd_HHmmss_SHA256SUMS.txt
```

JSON은 스키마 1.0의 구조화 DTO입니다. CSV는 `section,key,value` 형식과 UTF-8 BOM을 유지합니다. HTML은 스크립트·외부 CSS·이미지 없이 인코딩된 값과 내장 CSS만 사용합니다. CSV와 HTML은 같은 안전 DTO 필드 목록을 사용하므로 형식마다 진단 필드가 누락되지 않습니다.

## 공개 데이터와 근거

실행·출처·계획·분석 상태, 비교 상태·관계·고정 코드, 후보 수, DIRECT 위치, 알려진 인터페이스 범주, 10자리 호스트·인터페이스 지문을 저장합니다. 원문 URL, 프록시 지시문, 실제 호스트, 전체 GUID, 인터페이스 이름·설명, 원본 route evidence와 자유형 경고·예외 메시지는 복사하지 않습니다.

- 누락 상태는 `None`, 알 수 없는 상태는 `Unknown`으로 구분합니다.
- 누락되거나 정의되지 않은 인터페이스 범주는 빈 필드로 남깁니다.
- 비어 있는 일반 프록시 범위와 명시적 `all`만 전체 범위입니다. 알 수 없는 범위를 `all`로 확장하지 않고 `unknown`으로 표시합니다.
- CSV 수식 시작 문자를 비활성화하고 HTML 동적 값을 인코딩합니다.
- 짧은 지문은 표시용 축약값이지 익명성·기밀성 보장이 아닙니다. 후보를 이미 아는 사람은 추측해 대조할 수 있습니다.
- `Completed`는 진단 실행 종료이며 네트워크 정상 판정이 아닙니다. `Ready`도 첫 로컬 NIC가 같다는 의미일 뿐입니다.

## 파일 묶음의 완료 시점

먼저 전체 보고서를 메모리에서 렌더링합니다. 같은 이름의 협조적 동시 저장을 막기 위해 `FileMode.CreateNew` 예약 파일을 확보하고, 같은 출력 폴더의 임시 하위 폴더에 세 파일을 작성합니다. CSV BOM을 포함한 실제 파일 바이트로 SHA-256을 계산합니다.

```text
렌더링 → 이름 예약 → 임시 파일 작성 → 실제 바이트 해시
  → JSON 게시 → CSV 게시 → HTML 게시 → SHA256SUMS 게시
```

**SHA256SUMS의 마지막 게시가 저장 완료 시점입니다.** 네 파일이 동시에 원자적으로 나타나는 것은 아닙니다. 체크섬 목록이 없는 묶음은 미완료로 취급하십시오. 체크섬이 있어도 세 파일의 실제 해시와 일치해야 합니다.

같은 이름으로 동시에 저장하면 접미사 `_1`, `_2` 등을 선택합니다. 기존 파일·디렉터리·다른 저장 작업의 예약 파일을 덮어쓰거나 삭제하지 않습니다. 출력은 신뢰할 수 있는 로컬 디렉터리를 전제로 합니다. 파일을 임의 변경하는 적대적 외부 프로세스까지 격리하는 보안 경계는 아닙니다.

## 실패·취소·정리

완료 전 취소 또는 처리 가능한 파일 오류가 발생하면 이번 실행이 실제 게시한 파일만 정리합니다. 늦게 생긴 충돌 파일, 기존 보고서와 임시 폴더의 예상하지 못한 파일은 보존합니다. 임시 폴더는 재귀 삭제하지 않습니다.

| 결과 | 처리 |
|---|---|
| 저장 실패, 정리 성공 | 원래 오류 또는 취소 결과를 유지 |
| 저장 실패, 정리도 실패 | `ReportFileSetRecoveryException`으로 복구 확인 필요 표시 |
| 저장 완료, 임시 정리 실패 | 성공을 유지하고 `CleanupIncomplete` 경고 표시 |
| 체크섬 게시 뒤 취소 | 이미 완료된 보고서를 취소하거나 삭제하지 않음 |

취소 토큰이 켜져 있더라도 복구 필요 오류를 일반 취소로 숨기지 않습니다. 이전 성공 보고서는 유지됩니다. 파일 작업 도중 강제 종료·전원 차단·OS 종료가 발생한 경우의 자동 복구는 구현하지 않았습니다.

## 저장 작업 수명 관리

`ReportSaveSession`은 UI나 파일 API에 의존하지 않고 한 번에 하나의 저장 작업과 취소 토큰의 수명만 소유합니다.

```text
Idle → Running → CancellationRequested → Idle
                  또는 CloseAsync → Closing → Closed
```

- 중복 시작 요청은 거부하고 그 콜백은 실행하지 않습니다.
- 파일 렌더링과 쓰기는 스레드 풀에서 수행합니다.
- 취소 요청은 비동기 콜백을 사용하며 UI에서 `.Wait()`·`.Result`로 기다리지 않습니다.
- 저장 작업과 취소 콜백이 모두 끝난 다음 토큰 소스를 해제합니다.
- 성공한 저장 결과를 늦은 취소로 바꾸지 않습니다.
- 예외는 원래 작업 Task에 유지하며 종료용 대기는 작업을 합류시키는 용도로만 사용합니다.
- 취소 콜백 예외는 원문을 노출하지 않고 고정 경고 플래그로 구분합니다.

## 일반 창 닫기

저장 중 X 버튼·Alt+F4 같은 일반 창 닫기는 `Closing`에서 보류합니다. 취소를 요청하고 저장·정리와 UI 결과 처리가 끝난 뒤 Dispatcher로 다시 닫기를 요청합니다. 원래 Closing 이벤트 안에서 Close를 재귀 호출하지 않습니다.

정리 실패나 저장 오류를 확인해야 하면 창을 유지해 결과를 보여줍니다. 실제 창 종료 뒤에는 후속 UI 갱신을 하지 않고 등록 이벤트를 해제합니다.

이는 일반 창 닫기에 대한 처리입니다. 강제 프로세스 종료, OS 로그오프, 전원 차단, `Application.Shutdown()`처럼 Closing 취소가 보장되지 않는 경로까지 기다림을 보장하지 않습니다. 디스크 flush도 전원 장애에 대한 완전 영속성 보장이 아닙니다.

## UI 동시 실행 경계

측정·브라우저 관찰·경로 비교가 실행 중이면 보고서 저장을 시작하지 않습니다. 보고서 저장 중에는 해당 보고서 탭을 제외한 다른 탭의 기존 활성 상태를 보존해 비활성화하고, 중간에 추가된 탭도 잠급니다. 종료 후 기존 활성 상태를 복원하고 이벤트를 해제합니다.

이 단계는 UI 입력을 통한 동시 실행 제어와 보고서 저장 자체의 중복 방지입니다. 모든 프로그램 내부 호출까지 하나의 공통 실행 잠금으로 통합한 중앙 작업 관리자는 아직 아닙니다.

## 자동 검사

`ReportSmoke`에 기존 개인정보·JSON·CSV·HTML 테스트와 함께 다음을 연결합니다.

- 파일 저장 17개 그룹: 실제 해시/BOM, 32개 동시 저장, 파일·예약 보존, 4단계 임시 쓰기 실패, 4단계 게시 실패, 늦은 충돌, 취소 시점, 정리 실패, 완료 표식 순서, 미확인 임시 파일 보존, 잘못된 파일명·UTF-16.
- 저장 세션 12개 시나리오: 중복 시작, 취소 뒤 재시작, 실패 보존, 늦은 취소 성공 유지, 콜백 해제 순서, 콜백 오류, 종료 대기, 동시 시작, 취소·완료 경쟁과 복구 오류 우선순위.
- 보고서 경계: 실행 상태 9개, 비교 상태 4개, 프록시 범위 5개, 누락/알 수 없는 상태 구분.
- `test-route-report-save-ui-contract.ps1`: 저장 취소 토큰 연결, Closing 대기, 이벤트 해제, 직접 네트워크/원문 예외 출력 금지의 소스 계약 검사. 실제 WPF 상호작용 테스트를 대체하지 않습니다.
- `test-diagnostic-guide-package-cases.ps1`: 17개 문서를 담은 합성 ZIP의 정상·역슬래시·누락·빈 파일·대소문자 오류·중복·대소문자 충돌·구분자 충돌 8개 사례.

실제 회사 프록시·VPN·Windows UI 상호작용과 EDR 정책 검증은 사용자 환경에서 별도로 수행합니다.
