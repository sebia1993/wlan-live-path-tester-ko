# 반복 측정의 실행·중지·진행 알림

## 이번 변경

반복 측정은 기존 MainWindow가 소유한 ApplicationOperationCoordinator와 ApplicationOperationUiSession을 그대로 사용합니다. 새 전역 조정기·DispatcherTimer·ModuleInitializer를 만들지 않습니다.

기본 다운로드는 DownloadMeasurement, 반복 다운로드는 RepeatedMeasurement라는 고정 종류로 기록합니다. 두 기능 모두 RunCoordinatedMeasurementAsync에서 lease 획득·기존 취소 토큰·공통 UI 복원·lease 반환을 수행합니다. 기존 2인자 RunMeasurementOperationAsync는 단일 다운로드의 호환 진입점으로 남습니다.

## 같은 탭에서 중지

반복 측정 탭에 `반복 측정 중지` 버튼을 추가했습니다. 다른 탭을 잠가도 해당 버튼은 실행 중인 반복 측정의 lease를 통해 취소를 요청할 수 있습니다.

- 실행 중: 반복 시작·횟수·예열·대기 설정 잠금, 중지 활성
- 취소 요청 후: 중지 비활성, 실제 작업 종료 전까지 실행권 유지
- 완료·오류 후: 기존 공통 설정과 반복 설정 복원 후 실행권 반환
- 창 종료: 기존 공통 deferred-close가 같은 lease의 실제 완료를 기다림

동기 WinHTTP 호출은 즉시 끊지 않습니다. 기존 제한 시간과 협력적 취소를 유지하며 현재 호출이 실제로 반환되기 전에 완료로 표시하지 않습니다. 본 변경은 안전한 비동기 WinHTTP 전송의 대체물이 아닙니다.

## 진행 알림 식별

Progress<T> 알림은 Dispatcher에 예약되므로 대상 완료나 새 실행 뒤에 도착할 수 있습니다. 업데이트를 표시하려면 다음을 모두 만족해야 합니다.

1. 현재 UI lease와 정확히 같은 실행
2. 현재 반복 측정 lease 필드와 동일한 인스턴스
3. 현재 대상의 토큰 객체와 동일한 인스턴스
4. 취소 요청 없음
5. 창이 닫히지 않음

대상 번호는 알림 생성 당시의 1-based ordinal을 캡처합니다. 늦은 콜백에서 mutable results.Count를 읽지 않습니다. 대상 runner 반환 직후, 다음 대상이나 최종 결과를 표시하기 전에 대상 토큰을 무효화합니다.

따라서 이전 대상이 다음 대상으로 잘못 표시되거나 이전 실행의 알림이 최신 결과를 덮어쓰지 않습니다.

## 취소·실패 시 결과

이미 반환된 대상별 RepeatedMeasurementResult는 최종 화면에 유지합니다. 기존 runner가 기록하는 메모리 이력과 통계 계산을 교체하지 않습니다.

- 사용자가 취소한 뒤 runner가 정상 결과를 늦게 반환: 확보한 결과로 보존하되 작업 전체는 취소됨으로 표시
- runner가 Canceled 또는 미완료 결과 반환: 다음 대상 시작 중단
- 대상 2에서 예외 발생: 대상 1 결과 유지, 대상 3 이후 미시작
- 취소된 대상으로부터 아직 반환되지 않은 샘플: UI가 임의 생성하지 않음
- 결과 확보 대상 수와 미시작 대상 수를 별도로 표시

오류 유형만 표시하며 예외 메시지·내부 경로·URL을 오류 문장에 반사하지 않습니다. 이는 기존 입력 표시나 사용자 승인 URL 정책 자체를 변경하는 기능이 아닙니다.

## 입력·계획 보존

실행 전에 대상 배열과 HEAD preflight 설정을 캡처합니다. 실행 중 원본 배열이나 UI 값이 변경돼도 이미 시작한 계획은 바뀌지 않습니다.

기존 본 측정 1~5회·예열 옵션·대기 0~10000ms·대상당 및 작업 전체 2GiB 제한을 유지합니다. 주입 가능한 실행 진입점도 1~4개 대상, 양수 수신량, 계획 유효성, checked 총량 계산과 작업 전체 상한을 다시 검사합니다.

## 회귀 테스트

RepeatedUiSmoke는 실제 WPF STA Dispatcher, 실제 MainWindow·TabControl·Button.Click·Closing/Closed를 사용합니다. 창은 Show하지 않고 측정 runner를 합성 delegate로 주입합니다. Loaded/Activated의 네이티브 수집과 실제 WLAN·DNS·HTTP·PAC/WPAD 호출을 시작하지 않습니다.

11개 그룹:

- 대상 배열·계획·HEAD 옵션 스냅샷
- 같은 조정기를 통한 중복 반복/단일 측정 차단
- 실제 중지 버튼의 취소 한 번·실제 반환 대기
- 동기 완료 후 예약된 알림의 최종 결과 덮어쓰기 차단
- 이전 대상의 늦은 알림 차단과 대상 번호 보존
- 이전 실행의 늦은 알림 차단
- 예외 시 앞선 대상 결과 보존·원문 예외 비노출
- 실제 창 닫기의 취소·종료 대기
- 잘못된 계획·총량·오버플로에서 runner 0회
- 취소 결과 반환 시 이후 대상 runner 0회
- 탭 중복 등록 방지와 닫힌 창의 실행 차단

각 그룹은 5초 대기 상한, 전체 harness는 60초 상한을 가집니다. 검증 상태는 최종 PR head의 CI 로그로 별도 확인합니다. 테스트 작성 자체가 실행 성공은 아닙니다.

## 통신·의존성 경계

기존 사용자 실행 HEAD/GET 및 OS 프록시 인증은 유지합니다. runtime NuGet, AI·로컬 AI, 외부 분석 API, 텔레메트리, 결과 업로드, 자동 업데이트와 프록시 관리 API를 추가하지 않습니다.

## 후속

다른 진단·보고서 저장·자동 환경 갱신의 같은 UI 수명 이행, 통합 경로 보고서, 나머지 원문 입력 계층 감사, 문서 패키징 및 별도 공개 배포 검증은 남아 있습니다. 실제 회사 환경 검증은 사용자 담당입니다.
