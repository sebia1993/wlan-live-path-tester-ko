# 로컬 진단 보고서

## 목적

WLAN Live Path Tester KO는 현재 화면에 수집된 WLAN·프록시·내부망·외부망·브라우저 관찰 결과를 현재 PC에만 저장합니다. 보고서 생성은 네트워크 요청을 만들지 않으며 업로드, 텔레메트리, 공유 링크 생성과 온라인 분석을 수행하지 않습니다.

## 출력 위치

기본 경로:

```text
문서\WLAN Live Path Tester KO\Reports
```

문서 폴더를 확인할 수 없는 환경에서는 실행 파일이 있는 로컬 디렉터리를 사용합니다.

한 번 생성할 때 같은 기본 이름의 파일 네 개를 만듭니다.

```text
WlanLivePathTester_yyyyMMdd_HHmmss.json
WlanLivePathTester_yyyyMMdd_HHmmss.csv
WlanLivePathTester_yyyyMMdd_HHmmss.html
WlanLivePathTester_yyyyMMdd_HHmmss_SHA256SUMS.txt
```

같은 초에 다시 생성하거나 이름이 충돌하면 `_1`, `_2`처럼 새 이름을 사용하고 기존 파일을 덮어쓰지 않습니다.

## 포맷

### JSON

- 스키마 버전 `1.0`
- 실행 메타데이터
- 현재 WLAN 상태
- 현재 사용자 프록시 설정 존재 여부
- 화면에 남아 있는 측정 결과
- 브라우저 관찰 요약과 시간축 샘플
- 규칙 기반 Finding과 판단 한계
- UTF-8, 들여쓰기 적용

### CSV

- UTF-8 BOM을 포함해 Windows Excel에서 한글을 열기 쉽게 구성
- `section,key,value` 세 열의 긴 형식
- 모든 필드를 따옴표로 감싸고 내부 따옴표를 이스케이프
- 값이 `=`, `+`, `-`, `@`, 탭 또는 CR로 시작하면 작은따옴표를 붙여 수식 실행을 차단
- 측정 샘플과 Finding을 반복 행으로 기록

### 단일 HTML

- 외부 CSS, JavaScript, 웹폰트, 이미지, iframe 없음
- 모든 CSS를 파일 내부에 포함
- 사용자·측정 문자열을 HTML 인코딩
- Content Security Policy로 외부 리소스와 스크립트 실행 차단
- 화면과 인쇄에서 읽을 수 있는 반응형 카드·표 형식
- WLAN, 프록시, 측정, 브라우저 관찰, Finding과 한계를 한 파일에서 확인

### SHA-256

`SHA256SUMS.txt`에는 JSON, CSV, HTML의 SHA-256과 파일명을 기록합니다. 파일 전달 후 변경 여부를 확인할 때 사용할 수 있습니다. 해시는 파일의 무결성을 확인할 뿐 작성자 신원이나 회사 승인 여부를 증명하지 않습니다.

## 기본 마스킹

보고서에는 다음 원문을 기본적으로 포함하지 않습니다.

- SSID
- BSSID와 MAC 주소
- IPv4·IPv6 주소
- 이메일 주소
- Windows 사용자 프로필 경로
- URL 호스트와 쿼리 문자열
- 실제 프록시 주소
- PAC URL
- 프록시 바이패스 원문

URL은 가능한 경우 스킴과 안전하게 정리된 마지막 파일명만 남깁니다.

```text
https://[호스트 마스킹됨]/test.bin
```

WLAN 인터페이스 설명, HTTP 상태, Mbps, RSSI, 채널, PHY, 수신량과 오류 유형은 진단에 필요한 범위에서 유지합니다. 인터페이스 설명에 IP·MAC·URL·사용자 경로가 포함되면 텍스트 마스킹을 적용합니다.

## 규칙 기반 Finding

보고서는 자유 생성형 AI를 사용하지 않습니다. 고정된 규칙으로 다음과 같은 Finding을 만듭니다.

- WLAN 미연결 또는 약한 RSSI
- Windows 프록시 설정 읽기 실패
- HTTP 407 프록시 인증 실패
- 예상 DIRECT/PROXY 경로 불일치
- 측정 시간 초과
- HTTP 403 정책 또는 대상 접근 거부
- 낮은 신뢰도의 브라우저 관찰
- BSSID 변경과 처리량 정지·급락의 동시 관찰
- 명확한 실패 패턴이 없다는 제한적 결과

각 Finding에는 코드, 심각도, 근거, 제한된 해석, 판단 한계와 다음 확인 단계가 포함됩니다. 프록시 내부 상태나 특정 AP·컨트롤러·스위치 장애를 확인하지 못한 상태에서 원인을 확정하지 않습니다.

## 보고서 생성 시점의 의미

보고서 생성 버튼을 누르면 현재 WLAN과 현재 사용자 프록시 설정을 다시 로컬 API로 읽습니다. 따라서 과거 다운로드 측정 시점과 보고서 생성 시점의 WLAN 상태가 달라질 수 있습니다.

측정 결과는 선택되지 않은 탭까지 포함한 WPF 논리 트리의 이름 있는 결과·진행·상태 영역에서 가져와 마스킹한 텍스트로 저장합니다. 브라우저 관찰 결과는 마지막으로 완료되거나 중지된 관찰 요약과 샘플을 구조화해서 저장합니다.

측정 또는 브라우저 관찰이 진행 중일 때는 불완전한 상태를 저장하지 않도록 보고서 생성을 차단합니다.

## 공유 전 확인

자동 마스킹은 보조 수단입니다. 회사 밖이나 공개 Issue에 공유하기 전에는 다음을 직접 확인해야 합니다.

1. JSON, CSV, HTML 세 파일에서 실제 사내 도메인·주소·SSID·BSSID가 남지 않았는지 확인
2. 사용자 입력 문구나 오류 메시지에 사번·이름·내부 경로가 남지 않았는지 확인
3. 회사 보안 정책상 외부 공유가 허용되는지 확인
4. 전달한 파일과 `SHA256SUMS.txt`의 해시가 일치하는지 확인

프로그램은 보고서를 자동 전송하거나 외부에 공개하지 않습니다.

## 알려진 한계

- 일반 텍스트 기반 마스킹이 모든 조직 고유 식별자를 완벽히 인식한다고 보장하지 않습니다.
- 프록시 서버 CPU, 세션, 큐, 캐시와 정책 로그는 보고서에 포함되지 않습니다.
- 현재 운영체제의 `DIRECT` 판정은 투명 프록시가 없다는 증거가 아닙니다.
- 브라우저 관찰에는 다른 프로그램의 Wi-Fi 트래픽이 포함될 수 있습니다.
- PHY 링크 속도는 실제 다운로드 처리량이 아닙니다.
- 한 개 외부 사이트의 결과만으로 인터넷 회선이나 프록시 장애를 확정하지 않습니다.
- 자동 Finding이 없다는 결과는 전체 네트워크 정상이나 서비스 품질 보증을 의미하지 않습니다.

## 테스트 경계

자동 보고서 테스트는 합성 데이터와 임시 로컬 디렉터리만 사용합니다.

- 실제 회사 URL·프록시·SSID·BSSID 사용 안 함
- 외부 네트워크 요청 없음
- JSON 구문 확인
- CSV 수식 주입 방지
- HTML 인코딩·외부 리소스 미포함 확인
- 결정론적 Finding 확인
- JSON·CSV·HTML 생성과 SHA-256 재계산 확인
- 테스트 후 임시 파일 삭제
