# 브라우저 다운로드 관찰

## 목적

브라우저 전용 인증, 쿠키, SSO 또는 프록시 정책 때문에 프로그램의 WinHTTP 다운로드 측정이 실제 사용자 경로와 다를 수 있습니다. 이 모드는 프로그램이 외부 요청을 만들지 않은 상태에서 사용자가 Edge, Chrome 등으로 직접 다운로드할 때 **Wi-Fi 인터페이스 전체 수신량 변화**를 관찰합니다.

이 기능은 패킷 캡처나 브라우저 프로세스 후킹이 아닙니다. 다운로드 파일, URL, 쿠키, 세션, 인증 헤더와 패킷 본문을 읽지 않습니다.

## 관찰 순서

1. 현재 연결된 WLAN과 대응하는 Wi-Fi 인터페이스를 확인합니다.
2. 기본 3초 동안 백그라운드 수신 처리량을 측정합니다.
3. 화면이 실제 관찰 단계로 전환되면 사용자가 브라우저 다운로드를 시작합니다.
4. 기본 1초 간격으로 누적 Rx/Tx 바이트의 차이를 계산합니다.
5. 같은 시점의 RSSI, BSSID와 PHY 링크 속도를 함께 기록합니다.
6. 사용자가 지정한 시간이 끝나거나 중지 버튼을 누르면 로컬 요약을 생성합니다.

## 표시 지표

- 백그라운드 기준 수신 Mbps
- 기준치를 제외한 평균·최고 수신 Mbps
- 관찰 구간 전체 수신 바이트
- 일시 정지와 급격한 처리량 감소 횟수
- BSSID 변경 횟수
- Wi-Fi 인터페이스 변경 및 누적 카운터 재설정 횟수
- WLAN 연결 정보를 읽지 못한 샘플 수
- 결과 신뢰도

## 신뢰도

관찰값은 브라우저 프로세스 한 개의 전송량이 아니라 Wi-Fi 인터페이스 전체 트래픽입니다. 따라서 신뢰도는 최대 `중간`으로 제한합니다.

다음 조건에서는 `낮음`으로 표시합니다.

- 백그라운드 기준 트래픽이 높은 경우
- 실제 관찰 샘플이 부족한 경우
- 관찰 중 인터페이스가 변경된 경우
- 누적 카운터가 감소하거나 재설정된 경우
- WLAN 연결 정보를 일부 시점에 확인하지 못한 경우

결과가 낮은 신뢰도로 표시되면 클라우드 동기화, Windows Update, 백신, 메신저와 다른 다운로드 작업을 종료한 뒤 다시 측정하는 것이 좋습니다.

## 해석 원칙

### 프로그램 측정 실패, 브라우저 관찰 정상

브라우저 전용 SSO, 프록시 인증 캐시, 쿠키 또는 브라우저 정책 차이 가능성이 있습니다. 인터넷 회선이나 무선망 장애로 바로 판단하지 않습니다.

### 브라우저 관찰 중 BSSID 변경

로밍이 발생했을 가능성이 있습니다. 변경 시점 전후의 RSSI와 처리량 급락·정지 여부를 함께 확인합니다. BSSID 변경만으로 로밍 실패라고 단정하지 않습니다.

### PHY 링크 속도는 높지만 관찰 처리량이 낮음

PHY 링크 속도는 단말과 AP 사이의 협상 속도이며 실제 다운로드 처리량이 아닙니다. 무선 재전송, 채널 사용률, WLAN 터널, 사내 유선망, 프록시, 외부 사이트와 다른 프로세스 트래픽의 영향을 추가로 확인해야 합니다.

### 여러 번 반복해 같은 구간에서 정지

브라우저·사이트·프록시·외부 경로의 공통 패턴일 수 있습니다. 단일 관찰만으로 특정 장비나 프록시 서버 장애를 확정하지 않습니다.

## 데이터 및 통신 경계

- 프로그램 자체 외부 요청 없음
- 패킷 캡처 없음
- 브라우저 프로세스·쿠키·프로필 접근 없음
- 다운로드 파일과 URL 수집 없음
- WLAN 및 인터페이스 정보 외부 전송 없음
- 결과 업로드·텔레메트리·자동 오류 보고 없음
- 결과는 현재 실행 중인 PC 메모리와 향후 로컬 보고서에만 사용

## 수동 검증 항목

실제 Windows 11 PC에서는 다음을 확인합니다.

- 연결된 WLAN과 실제 Wi-Fi NIC가 올바르게 매칭되는지
- 유선·VPN·가상 어댑터가 함께 있을 때 Wi-Fi NIC를 선택하는지
- 절전, 어댑터 재시작, 로밍 시 카운터 경계가 안전한지
- 회사 GPO·EDR 환경에서 인터페이스 통계 조회가 허용되는지
- 브라우저 다운로드와 표시된 처리량의 경향이 일치하는지

실제 SSID, BSSID, 내부 주소, 프록시 주소와 원시 결과는 공개 저장소에 커밋하지 않습니다.
