# 브라우저 다운로드 관찰

## 목적

브라우저 전용 인증, 쿠키, SSO 또는 프록시 정책 때문에 프로그램의 WinHTTP 다운로드 측정이 실제 사용자 경로와 다를 수 있습니다. 이 모드는 프로그램이 외부 요청을 만들지 않은 상태에서 사용자가 Edge, Chrome 등으로 직접 다운로드할 때 **시작 시 고정한 물리 Wi-Fi 인터페이스의 전체 수신량 변화**를 관찰합니다.

이 기능은 패킷 캡처나 브라우저 프로세스 후킹이 아닙니다. 다운로드 파일, URL, 쿠키, 세션, 인증 헤더와 패킷 본문을 읽지 않습니다.

## 관찰할 Wi-Fi NIC 선택

브라우저 관찰은 아무 활성 Wi-Fi나 첫 번째로 선택하지 않습니다. 다음 순서로 현재 연결된 Native WLAN과 동일한 물리 Wi-Fi 카운터를 선택합니다.

```text
1. Native WLAN 현재 연결 확인
2. WlanEnumInterfaces의 연결 identity로 인터페이스 GUID 보완
3. 물리 Wi-Fi 후보만 유지하고 Wi-Fi Direct·가상·VPN 후보 제외
4. 유효한 인터페이스 GUID 완전 일치
5. 시작 시 GUID가 없을 때만 설명 완전 일치
6. 식별정보가 전혀 없을 때는 Up 상태 물리 Wi-Fi가 정확히 한 개인 경우만 선택
7. 중복·미일치·비활성 상태에서는 관찰 시작 차단
8. 선택된 카운터 ID를 관찰이 끝날 때까지 고정
```

다음 상황에서는 다른 Wi-Fi NIC로 자동 우회하지 않습니다.

- Native WLAN GUID와 일치하는 로컬 Wi-Fi가 없음
- 같은 GUID를 가진 후보가 여러 개임
- 같은 설명을 가진 후보가 여러 개임
- 대응된 Wi-Fi가 Up 상태가 아님
- Native WLAN 식별정보가 없고 활성 물리 Wi-Fi가 여러 개임
- 시작 시 고정한 NIC를 관찰 중 더 이상 읽을 수 없음
- Native WLAN 연결이 다른 물리 Wi-Fi ID로 변경됨
- 카운터 공급자가 고정 ID와 다른 인터페이스 결과를 반환함

이 fail-closed 동작은 잘못된 NIC의 높은 트래픽을 현재 WLAN 다운로드 속도로 오판하는 것보다 관찰을 중단하는 편이 안전하기 때문입니다.

## 관찰 순서

1. 현재 연결된 WLAN과 정확히 대응하는 물리 Wi-Fi 인터페이스를 확인합니다.
2. Native WLAN ID와 첫 카운터 ID가 일치하는지 확인하고 카운터 ID를 고정합니다.
3. 기본 3초 동안 고정된 NIC의 백그라운드 수신 처리량을 측정합니다.
4. 화면이 실제 관찰 단계로 전환되면 사용자가 브라우저 다운로드를 시작합니다.
5. 기본 1초 간격으로 동일 ID의 누적 Rx/Tx 바이트만 읽습니다.
6. 같은 시점의 RSSI, BSSID와 PHY 링크 속도를 함께 기록합니다.
7. 같은 NIC의 BSSID 변경은 로밍으로 기록하고 관찰을 계속합니다.
8. 물리 NIC ID가 변경되거나 고정 카운터를 읽을 수 없으면 별도 종료 상태로 중단합니다.
9. 사용자가 지정한 시간이 끝나거나 중지 버튼을 누르면 로컬 요약을 생성합니다.

## 구조화된 종료 상태

사용자 중지와 인터페이스 문제를 문장만으로 구분하지 않고 다음 상태값으로 저장합니다.

| 상태 | 의미 |
|---|---|
| `Success` | 계획된 관찰 완료 |
| `PartialSuccess` | 일부 결과는 있으나 일반 오류로 조기 종료 |
| `Canceled` | 사용자가 중지하거나 취소 토큰이 취소됨 |
| `AdapterChanged` | Native WLAN 연결이 시작 시 고정한 물리 Wi-Fi와 다른 ID로 변경됨 |
| `AdapterUnavailable` | 시작 시 고정한 Wi-Fi 카운터를 더 이상 읽을 수 없음 |
| `CounterProviderMismatch` | 카운터 공급자가 고정 ID와 다른 NIC 결과를 반환하거나 초기 WLAN·카운터 ID가 충돌함 |
| `NoWirelessConnection` | 관찰 시작 시 연결 WLAN 없음 |
| `InterfaceUnavailable` | 시작 시 사용할 물리 Wi-Fi 통계를 확보하지 못함 |

`AdapterChanged`, `AdapterUnavailable`, `CounterProviderMismatch`는 일반 성공으로 취급하지 않습니다. 중단 전에 수집된 정상 샘플이 있으면 요약은 보존하지만 상태는 그대로 유지합니다.

## 표시 지표

- 백그라운드 기준 수신 Mbps
- 기준치를 제외한 평균·최고 수신 Mbps
- 관찰 구간 전체 수신 바이트
- 일시 정지와 급격한 처리량 감소 횟수
- BSSID 변경 횟수
- 방어적으로 감지된 카운터 ID 변경 및 누적 카운터 재설정 횟수
- WLAN 연결 정보를 읽지 못한 샘플 수
- 결과 신뢰도
- 구조화된 종료 상태

## 신뢰도

관찰값은 브라우저 프로세스 한 개의 전송량이 아니라 선택된 Wi-Fi 인터페이스 전체 트래픽입니다. 따라서 신뢰도는 최대 `중간`으로 제한합니다.

다음 조건에서는 `낮음`으로 표시합니다.

- 백그라운드 기준 트래픽이 높은 경우
- 실제 관찰 샘플이 부족한 경우
- 누적 카운터가 감소하거나 재설정된 경우
- WLAN 연결 정보를 일부 시점에 확인하지 못한 경우
- 일반 오류로 일부 샘플만 수집된 경우

물리 NIC 변경이나 카운터 공급자 불일치는 신뢰도만 낮추는 대신 전용 상태로 관찰 자체를 종료합니다.

## 해석 원칙

### 프로그램 측정 실패, 브라우저 관찰 정상

브라우저 전용 SSO, 프록시 인증 캐시, 쿠키 또는 브라우저 정책 차이 가능성이 있습니다. 인터넷 회선이나 무선망 장애로 바로 판단하지 않습니다.

### 브라우저 관찰 중 BSSID 변경

같은 인터페이스 ID에서 BSSID만 변경되면 로밍이 발생했을 가능성이 있습니다. 변경 시점 전후의 RSSI와 처리량 급락·정지 여부를 함께 확인합니다. BSSID 변경만으로 로밍 실패라고 단정하지 않습니다.

### `AdapterChanged`

내장 Wi-Fi에서 USB Wi-Fi로 전환되는 등 Native WLAN의 물리 인터페이스 ID가 바뀐 경우입니다. 서로 다른 NIC의 누적 카운터를 결합하지 않고 관찰을 중단합니다. 사용하지 않는 Wi-Fi를 비활성화하거나 실제 연결 NIC를 확인한 뒤 새 관찰을 시작합니다.

### `AdapterUnavailable`

시작 시 고정한 물리 Wi-Fi가 비활성화·제거·드라이버 재시작 등으로 통계 목록에서 사라졌거나 Up 상태가 아닌 경우입니다. 다른 활성 Wi-Fi가 있어도 자동 대체하지 않습니다.

### `CounterProviderMismatch`

Native WLAN ID와 카운터 ID가 처음부터 다르거나, 저수준 카운터 공급자가 고정 ID와 다른 값을 반환한 방어적 오류입니다. 결과를 실제 WLAN 처리량으로 사용하지 말고 인터페이스 환경과 드라이버 상태를 확인합니다.

### WLAN NIC 대응 실패

브라우저 관찰은 시작하지 않습니다. 먼저 `인터페이스 환경`과 `WLAN NIC 대응` 탭에서 다음을 확인합니다.

- 내장·USB Wi-Fi가 동시에 활성화됐는지
- Wi-Fi Direct 가상 어댑터가 있는지
- Native WLAN 설명과 로컬 NIC 설명이 다른지
- 대응된 NIC가 Up 상태인지
- 유선 또는 VPN 기본 경로가 함께 활성화됐는지

### PHY 링크 속도는 높지만 관찰 처리량이 낮음

PHY 링크 속도는 단말과 AP 사이의 협상 속도이며 실제 다운로드 처리량이 아닙니다. 무선 재전송, 채널 사용률, WLAN 터널, 사내 유선망, 프록시, 외부 사이트와 다른 프로세스 트래픽의 영향을 추가로 확인해야 합니다.

## 데이터 및 통신 경계

- 프로그램 자체 외부 요청 없음
- 패킷 캡처 없음
- 브라우저 프로세스·쿠키·프로필 접근 없음
- 다운로드 파일과 URL 수집 없음
- WLAN 및 인터페이스 정보 외부 전송 없음
- 결과 업로드·텔레메트리·자동 오류 보고 없음
- 인터페이스 GUID는 로컬 NIC 선택과 연속성 확인에만 사용
- 전체 GUID는 화면·일반 보고서·외부 전송에 포함하지 않음
- 결과는 현재 실행 중인 PC 메모리와 로컬 보고서에만 사용

## 자동 검증

Windows CI에서 다음 경계를 매 PR마다 확인합니다.

- 정확 ID 강제 모드가 같은 설명의 다른 Wi-Fi로 우회하지 않음
- GUID 중괄호·대소문자 정규화
- 초기 Native WLAN·카운터 ID 불일치 거부
- 관찰 중 명시적인 Native WLAN ID 변경 감지
- 일시적인 WLAN ID 미확인 시 고정 카운터 유지
- 카운터 공급자 ID 불일치 감지
- 구조화 종료 상태의 보고서 매핑
- 기존 카운터 차이·BSSID 변경·정지·급락 계산 회귀

실제 외부 사이트나 회사 프록시는 자동 시험에서 호출하지 않습니다.

## 수동 검증 항목

실제 Windows 11 PC에서는 다음을 확인합니다.

- 연결된 Native WLAN과 실제 Wi-Fi NIC가 GUID로 올바르게 대응되는지
- GUID를 읽지 못할 때 시작 시 설명 완전 일치가 정확히 동작하는지
- 내장·USB Wi-Fi가 함께 활성화된 상태에서 잘못된 NIC로 우회하지 않는지
- Wi-Fi Direct·VPN·가상 어댑터를 물리 Wi-Fi 관찰 대상으로 선택하지 않는지
- 관찰 중 USB Wi-Fi 제거 또는 내장 Wi-Fi 전환 시 `AdapterChanged` 또는 `AdapterUnavailable`로 종료되는지
- 같은 물리 Wi-Fi에서 BSSID만 바뀌는 로밍은 관찰이 유지되는지
- 절전 복귀와 Wi-Fi 드라이버 재시작 시 상태가 정확히 구분되는지
- 회사 GPO·EDR 환경에서 WLAN identity와 인터페이스 통계 조회가 허용되는지
- 브라우저 다운로드와 표시된 처리량의 경향이 일치하는지

실제 SSID, BSSID, 내부 주소, 프록시 주소, 인터페이스 GUID와 원시 결과는 공개 저장소에 커밋하지 않습니다.
