# 네트워크 통신 경계

## 모드별 정책

### 애플리케이션 시작 및 로컬 상태 확인

- 외부 통신 없음
- 현재 WLAN 및 Windows 프록시 설정은 로컬 OS API로만 조회
- PAC URL이 존재해도 사용자가 대상 URL의 경로 확인 또는 측정을 실행하기 전에는 PAC 파일을 다운로드하지 않음

### 대상 URL별 프록시 경로 확인

- 사용자가 URL을 입력하고 별도 버튼을 눌렀을 때만 실행
- 수동 프록시·바이패스만 설정된 경우 로컬 계산으로 종료
- WPAD 또는 PAC가 설정된 경우 회사 내부 PAC 파일 조회·WPAD 탐색·PAC 평가가 발생할 수 있음
- PAC 스크립트가 요구하는 DNS 확인이 발생할 수 있음
- 대상 사이트 파일 본문은 다운로드하지 않음
- 프록시 주소와 PAC URL은 기본 화면 및 public 결과에서 마스킹

### 내부망 측정

- 사용자가 등록한 승인 내부 URL에만 `HEAD` 또는 `GET`
- 예상 경로는 `DIRECT` 또는 명시적 바이패스
- 프록시를 경유하면 내부망 순수 측정으로 판정하지 않음

### 외부망 측정

- 사용자가 등록한 승인 외부 URL에만 `HEAD` 또는 `GET`
- 현재 로그인 사용자의 Windows 프록시/PAC/WPAD 정책을 적용
- 다운로드 데이터는 파일로 저장하지 않고 즉시 폐기
- 외부 사이트에 업로드 요청을 보내지 않음

### 브라우저 다운로드 관찰

- 프로그램이 외부 요청을 생성하지 않음
- WLAN 인터페이스의 누적 바이트 카운터 변화만 로컬에서 관찰

## 금지 대상

- 텔레메트리
- 자동 업데이트
- 서버 자동 검색
- 공인 IP, ISP, 위치 조회
- AI 또는 외부 분석 API
- 측정 결과 업로드
- 실제 캡처·로그 업로드
- 외부 POST/PUT/PATCH/DELETE
