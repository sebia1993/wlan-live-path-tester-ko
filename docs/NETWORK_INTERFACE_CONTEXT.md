# 로컬 인터페이스 환경 진단

이 기능은 실제 다운로드가 어느 인터페이스로 나갈 수 있는지 해석할 때 혼동을 줄이기 위해 Windows의 로컬 네트워크 인터페이스 환경을 요약합니다.

## 통신 경계

인터페이스 환경 확인은 다음 로컬 API만 사용합니다.

```text
System.Net.NetworkInformation.NetworkInterface
```

다음 작업은 수행하지 않습니다.

- DNS 조회
- HTTP/HTTPS 요청
- 프록시 또는 PAC/WPAD 조회
- 외부 API 호출
- 공인 IP·ISP·GeoIP 조회
- 인터페이스 정보 업로드

화면에는 인터페이스 이름과 설명, 유형, 상태, 링크 속도, 주소 계열 유무와 개수, 기본 게이트웨이 유무와 개수만 표시합니다. 다음 원문은 표시하지 않습니다.

- IPv4·IPv6 주소
- 기본 게이트웨이 주소
- DNS 서버 주소
- MAC 주소
- DHCP 서버 주소

## 분류 대상

프로그램은 Windows 네이티브 인터페이스 유형과 로컬 이름·설명의 제한된 키워드를 함께 사용해 다음 범주를 구분합니다.

- 물리 Wi-Fi 후보
- 물리 Ethernet 후보
- VPN 또는 터널
- Hyper-V `vEthernet`
- VMware·VirtualBox
- WSL·Docker·컨테이너 가상 NIC
- Wi-Fi Direct 가상 어댑터
- Loopback 및 기타 인터페이스

VPN·가상 분류는 장치 이름과 설명에 대한 휴리스틱입니다. 제품명이나 드라이버 표기가 다르면 분류되지 않을 수 있으므로 실제 라우팅을 확정하는 근거로 단독 사용하지 않습니다.

## 주요 판정

### 활성 물리 Wi-Fi 없음

Up 상태인 비가상 `Wireless80211` 인터페이스가 없으면 WLAN 관찰 결과를 실제 무선 경로와 연결하기 어렵다고 표시합니다.

### 물리 Wi-Fi 여러 개

내장 Wi-Fi와 USB Wi-Fi가 동시에 활성화된 경우 Native WLAN 상태 수집과 인터페이스 처리량 관찰이 서로 다른 NIC를 가리킬 수 있다고 경고합니다.

### 활성 기본 게이트웨이 여러 개

기본 게이트웨이 주소 자체는 표시하지 않고, Up 상태 인터페이스 중 게이트웨이를 가진 인터페이스 개수만 계산합니다.

두 개 이상이면 실제 목적지 경로가 Windows 라우팅 메트릭에 따라 결정되므로 다음 명령과 비교해야 합니다.

```powershell
route print
Get-NetRoute -AddressFamily IPv4 |
  Sort-Object DestinationPrefix, RouteMetric
Get-NetIPInterface |
  Sort-Object InterfaceMetric
```

### 유선·무선 기본 경로 동시 활성

유선과 Wi-Fi가 모두 기본 게이트웨이를 가지면 다운로드 요청은 유선으로 나가면서 WLAN 카운터는 Wi-Fi를 관찰하는 불일치가 생길 수 있습니다.

무선 성능만 검증할 때는 회사 정책 범위에서 유선을 분리하거나 목적지별 최적 경로의 인터페이스 인덱스를 확인합니다.

### VPN 또는 터널 활성

VPN·터널·보안 에이전트 후보가 활성화되면 내부·외부 요청이 물리 Wi-Fi 위의 별도 논리 경로를 통과할 수 있습니다.

VPN이 있다고 해서 문제가 있다는 의미는 아닙니다. 측정 당시 VPN 사용 여부를 보고서나 장애 기록에 함께 남기는 것이 목적입니다.

### 가상 어댑터 활성

Hyper-V·VMware·WSL 등의 가상 NIC는 대부분 직접적인 장애 원인이 아니지만 자동 인터페이스 선택과 카운터 해석을 복잡하게 만들 수 있습니다.

## 링크 속도 해석

인터페이스 목록의 링크 속도는 운영체제가 제공하는 어댑터 링크 속도입니다. Wi-Fi의 실제 다운로드 처리량이나 PHY 협상값과 동일하다고 간주하지 않습니다.

다음 값을 서로 구분합니다.

```text
어댑터 링크 속도
Native WLAN Rx/Tx PHY 링크 속도
내부망 HTTP 다운로드 처리량
프록시 포함 외부 HTTP 다운로드 처리량
브라우저 다운로드 중 Wi-Fi 인터페이스 처리량
```

## 권장 진단 순서

1. `인터페이스 환경` 탭에서 활성 Wi-Fi·유선·VPN·가상 NIC와 기본 게이트웨이 개수를 확인합니다.
2. `WLAN · 프록시` 탭에서 실제 연결된 SSID·BSSID·RSSI·채널을 확인합니다.
3. 유선·VPN·다중 Wi-Fi 경고가 있으면 목적지별 Windows 라우팅을 확인합니다.
4. 내부 URL의 DIRECT 경로와 외부 URL의 PROXY 경로를 확인합니다.
5. 내부·외부 다운로드 또는 반복 측정을 실행합니다.
6. 브라우저 관찰 결과와 실제 요청 경로가 같은 물리 Wi-Fi를 사용했는지 검토합니다.

## 판단 한계

- 기본 게이트웨이가 한 개여도 더 구체적인 목적지 경로가 다른 인터페이스를 선택할 수 있습니다.
- 프록시가 사용되면 로컬 PC의 최종 연결 목적지는 외부 사이트가 아니라 프록시일 수 있습니다.
- VPN split tunnel, NRPT, 보안 에이전트와 Windows Filtering Platform 정책은 인터페이스 목록만으로 완전히 판정할 수 없습니다.
- 인터페이스 이름 기반 VPN·가상 분류는 휴리스틱이며 오탐·누락 가능성이 있습니다.
- 실제 경로 확정에는 `Get-NetRoute`, `Get-NetIPInterface`, 프록시 판정과 측정 결과를 함께 사용해야 합니다.
