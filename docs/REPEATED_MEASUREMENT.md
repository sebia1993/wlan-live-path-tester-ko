# 반복 다운로드 측정

반복 측정은 한 번의 우연한 다운로드 결과 대신 여러 본 측정의 중앙값과 편차를 이용해 내부·외부 경로의 처리량을 비교하는 기능입니다.

외부 결과는 인터넷 회선만의 순수 속도가 아니라 다음 전체 경로의 체감 다운로드 성능입니다.

```text
무선 단말 → AP/컨트롤러 → 사내망 → 회사 프록시 → 외부 사이트 또는 CDN
```

프록시 서버 내부 상태에는 접근하지 않으므로 반복 결과가 낮아도 프록시 장애로 단정하지 않습니다.

## 실행 순서

1. `내부 · 외부 다운로드 측정` 탭에 URL과 공통 제한값을 입력하거나 승인 대상에서 적용합니다.
2. `반복 측정` 탭에서 본 측정 횟수, 예열 사용 여부와 측정 간 대기 시간을 선택합니다.
3. 내부 또는 외부 반복 측정을 시작합니다.
4. 예열을 선택한 경우 예열 1회가 먼저 실행되며 대표값·편차 계산에서는 제외됩니다.
5. 본 측정은 대상별로 순차 실행됩니다.
6. 외부 URL을 여러 개 입력한 경우 URL 간에도 순차 실행하여 대상 사이트에 불필요한 동시 부하를 주지 않습니다.

기본 권장값은 다음과 같습니다.

```text
본 측정: 3회
예열: 1회 사용
측정 간 대기: 500ms
```

## 전송량 경계

예열과 본 측정은 각각 실제 `HEAD` 및 `GET` 요청을 수행합니다. 외부 요청은 회사 프록시 경로가 확인된 경우에만 진행됩니다.

대상 하나의 최대 예상 수신량은 다음과 같습니다.

```text
대상별 maxBytes × (본 측정 횟수 + 예열 1회)
```

프로그램은 다음 상한을 적용합니다.

- 대상 하나의 반복 측정 최대 예상 수신량: 2GiB
- 한 번의 반복 측정 작업 전체 최대 예상 수신량: 2GiB
- 본 측정 횟수: 1~5회
- 측정 간 대기: 0~10000ms
- 외부 대상: 최대 4개

예를 들어 외부 URL 3개, URL별 최대 수신량 100MiB, 본 측정 3회와 예열 1회이면 최대 예상 수신량은 1.2GiB입니다.

## 대표값

대표 처리량은 성공한 본 측정 결과를 정렬한 중앙값입니다.

```text
예열 결과 → 제외
본 측정 결과 → 성공 결과만 정렬
대표값 → 중앙값
대표 회차 → 중앙값에 가장 가까운 실제 본 측정
```

두 개의 중앙값 후보가 있는 경우 두 값의 평균을 중앙값으로 사용하고, 실제 대표 회차는 그 값에 가장 가까운 앞선 성공 회차를 선택합니다.

함께 표시하는 값은 다음과 같습니다.

- 본 측정 계획·완료·성공·실패·미완료 횟수
- 중앙값
- 최소·최대
- 산술평균
- 모집단 표준편차
- 변동계수
- 대표 본 측정 회차
- 실제 총 수신량
- 캐시 적중 가능성
- 신뢰도와 판정 근거

## 신뢰도 규칙

신뢰도는 AI가 아닌 고정 규칙으로 계산합니다.

### 높음

다음 조건을 모두 충족할 때 가능합니다.

- 성공한 본 측정 3회 이상
- 실패와 미완료 없음
- 개별 결과가 낮은 신뢰도로 분류되지 않음
- 변동계수 20% 이하
- 프록시 또는 CDN 캐시 적중 근거 없음

### 중간

다음과 같은 경우입니다.

- 성공 결과는 충분하지만 3회 미만
- 변동계수 40% 이하
- 결과가 안정적이어도 캐시 적중 가능성이 있음

캐시 적중 가능성이 있으면 높은 신뢰도로 올리지 않습니다.

### 낮음

다음 중 하나가 해당하면 낮음으로 분류합니다.

- 성공한 본 측정 2회 미만
- 실행된 본 측정 실패
- 계획된 본 측정 미완료
- 수신량·측정 시간·스트림 완료 기준에서 낮은 신뢰도의 개별 결과 존재
- 변동계수 40% 초과

성공 결과가 하나도 없으면 대표값과 반복 신뢰도를 계산하지 않습니다.

## 캐시 해석

`Age`, `X-Cache`, `Cache-Status` 응답 헤더에 적중 근거가 있으면 캐시 적중 가능성을 표시합니다.

캐시 적중 상태에서 매우 빠른 결과는 외부 원본 서버까지의 전체 경로가 아니라 프록시 또는 CDN 캐시 성능일 수 있습니다. 반대로 관련 헤더가 없다고 해서 캐시가 없음을 증명하지는 않습니다.

## 취소

취소 버튼을 누르면 다음 반복, 다음 대상과 WinHTTP 호출 사이 단계는 중단됩니다.

현재 전송 엔진은 동기 WinHTTP를 사용하므로 이미 블로킹된 현재 호출은 설정된 제한 시간 안에 반환된 뒤 취소 상태가 반영될 수 있습니다. 동기 요청 핸들을 다른 스레드에서 강제로 닫지 않습니다. 블로킹 호출의 즉시 취소는 향후 비동기 WinHTTP 전송 계층에서 구현합니다.

## 반복 측정 보고서

`반복 보고서` 탭은 현재 앱 실행 중 메모리에 보관된 최근 반복 측정 최대 8건을 다음 파일로 저장합니다.

```text
WlanRepeatedMeasurement_yyyyMMdd_HHmmss.json
WlanRepeatedMeasurement_yyyyMMdd_HHmmss.csv
WlanRepeatedMeasurement_yyyyMMdd_HHmmss.html
WlanRepeatedMeasurement_yyyyMMdd_HHmmss_SHA256SUMS.txt
```

보고서에는 다음 항목이 구조화되어 기록됩니다.

- 반복 계획과 성공·실패·미완료 횟수
- 중앙값·최소·최대·평균·표준편차·변동계수
- 대표 회차, 캐시 가능성, 신뢰도와 근거
- 예열 및 각 본 측정의 상태·수신량·Mbps·TTFB·HTTP 상태·프록시 사용 여부

다음 정보는 반복 보고서에 넣지 않습니다.

- 대상 URL
- 프록시 주소
- PAC URL
- SSID와 BSSID
- 사용자 이름과 사용자 프로필 경로

CSV는 수식 시작 문자를 비활성화하고, HTML은 외부 JavaScript·스타일시트·웹폰트·이미지·iframe 없이 생성합니다. 앱 종료 시 메모리 이력은 사라지므로 필요한 보고서는 종료 전에 생성해야 합니다.

## 해석 예

| 내부 중앙값 | 외부 복수 대상 | 편차 | 해석 |
|---:|---:|---:|---|
| 정상 | 모두 낮음 | 낮음 | 프록시·인터넷 경계·공통 외부 경로 영향 가능성 |
| 정상 | 한 대상만 낮음 | 대상 간 큼 | 사이트·CDN·외부 개별 경로 차이 가능성 |
| 낮음 | 모두 낮음 | 낮거나 중간 | WLAN 또는 사내 내부 경로 우선 점검 |
| 정상 | 정상 | 높음 | 측정 대상·캐시·외부 경로 변동이 커 대표값 신뢰도 낮음 |

반복 측정도 프록시 내부 상태와 외부 서버 운영 지표를 직접 확인하지 않으므로 단독 장애 확정에 사용하지 않습니다.
