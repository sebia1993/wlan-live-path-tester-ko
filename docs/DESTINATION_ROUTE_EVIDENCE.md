# 목적지별 Windows 라우팅 근거

이 기능은 대상 주소에 대해 Windows가 선택하는 최적 로컬 인터페이스를 확인합니다. 내부 DIRECT 다운로드가 실제 Wi‑Fi가 아니라 유선·VPN·가상 인터페이스로 나가는 상황과 IPv4·IPv6별 경로 차이를 식별하는 보조 진단입니다.

## 사용 API

Windows의 다음 로컬 기능을 사용합니다.

```text
GetBestInterfaceEx (iphlpapi.dll)
NetworkInterface.GetAllNetworkInterfaces()
```

`GetBestInterfaceEx`는 목적지 주소에 대한 Windows 최적 인터페이스 인덱스를 반환합니다. 프로그램은 해당 인덱스를 로컬 `NetworkInterface`의 IPv4 또는 IPv6 인터페이스 인덱스와 대응시킵니다.

## 통신 경계

### IP 주소 입력

IPv4 또는 IPv6 리터럴을 입력하면 DNS·HTTP 요청 없이 현재 PC의 로컬 라우팅 테이블만 확인합니다.

```text
입력 IP
  ↓
GetBestInterfaceEx
  ↓
로컬 인터페이스 인덱스 대응
```

### 호스트 이름 또는 URL 입력

호스트 이름, `host:port`, HTTP 또는 HTTPS URL을 입력하면 사용자가 `Windows 최적 인터페이스 확인` 버튼을 누른 시점에 DNS 확인이 발생합니다.

```text
입력 호스트/URL
  ↓
로컬 DNS 확인
  ↓
반환된 IPv4·IPv6 주소별 GetBestInterfaceEx
```

다음 작업은 수행하지 않습니다.

- 대상에 대한 HTTP/HTTPS 요청
- 파일 다운로드 또는 업로드
- 외부 분석 API 호출
- 공인 IP·ISP·GeoIP 조회
- 텔레메트리·자동 오류 전송
- 결과 자동 업로드

DNS 확인 제한 시간은 5초이며 UI에서 취소할 수 있습니다.

## 지원 입력

- `192.0.2.10`
- `2001:db8::10`
- `[2001:db8::10]:8080`
- `internal.example`
- `proxy.example:8080`
- `http://internal.example/test.bin`
- `https://external.example/download.bin?cache=off`

HTTP와 HTTPS 외의 URL 스킴, URL 사용자 정보, fragment와 경로가 포함된 단순 `host:port` 오입력은 거부합니다.

## 해석 목적

### 내부 DIRECT 측정 대상

내부 기준 서버까지 Windows가 선택하는 인터페이스가 Wi‑Fi인지 확인합니다.

```text
Wi-Fi 선택
  → 무선 성능 측정 경로와 일치 가능성 높음

Ethernet/VPN/Virtual 선택
  → 다운로드 실측과 WLAN 상태가 서로 다른 경로일 가능성
```

내부 대상이 사설망 정적 경로를 사용하는 경우 선택 인터페이스에 기본 게이트웨이가 없어도 정상일 수 있습니다.

### 프록시 엔드포인트

PC에서 회사 프록시까지의 로컬 인터페이스 선택을 확인합니다. 이 결과에는 프록시 이후 인터넷 회선·외부 CDN·사이트 구간이 포함되지 않습니다.

### 외부 사이트 참고 경로

회사 프록시 구조에서는 외부 사이트 주소의 직접 최적 인터페이스가 실제 HTTP 연결 경로가 아닐 수 있습니다.

```text
프로그램 외부 측정의 실제 로컬 연결
PC → 회사 프록시

외부 사이트 참고 분석
PC → 외부 사이트 주소에 대한 로컬 라우팅 가정
```

PAC·WPAD 또는 수동 프록시가 선택한 엔드포인트를 알 수 있을 때는 `프록시 엔드포인트` 목적으로 확인해야 합니다. 외부 사이트 참고 결과만으로 Wi‑Fi·유선·VPN 사용을 확정하지 않습니다.

## IPv4·IPv6 결과

DNS가 여러 주소를 반환하면 최대 16개까지 IPv4 우선으로 확인합니다.

- 모든 성공 주소가 같은 인터페이스를 선택하면 단일 선택으로 표시합니다.
- 일부 주소만 확인되면 `일부 확인`으로 표시합니다.
- IPv4와 IPv6 또는 복수 주소가 서로 다른 인터페이스를 선택하면 `복수 인터페이스`로 표시하고 하나를 임의 선택하지 않습니다.
- 실제 애플리케이션이 어느 주소에 연결할지는 주소 선택·Happy Eyeballs·프록시 정책의 영향을 받을 수 있습니다.

## 표시 값

- 대상 구분
- DNS 사용 여부
- 확인한 주소 수
- Windows 선택 인터페이스 이름과 설명
- 인터페이스 유형과 Wi‑Fi·유선·터널·루프백 범주
- Up 상태
- 기본 게이트웨이 유무
- VPN·가상 분류
- 주소 계열별 선택 상태
- 인터페이스 ID SHA‑256 앞 10자리 지문

## 표시하지 않는 값

- DNS로 해석한 IPv4·IPv6 주소 원문
- 게이트웨이 주소
- DNS 서버 주소
- MAC 주소
- 전체 인터페이스 GUID
- 프록시 주소의 자동 추출값

인터페이스 ID는 로컬 결과 비교를 위한 짧은 지문만 표시합니다.

## 주요 경고

- 내부 DIRECT 대상의 최적 경로가 Wi‑Fi가 아님
- VPN 또는 터널 인터페이스 선택
- 가상 인터페이스 선택
- IPv4·IPv6가 서로 다른 인터페이스 선택
- 선택 인터페이스가 Up 상태가 아님
- 외부 사이트 참고 분석이 프록시 실제 경로와 다를 수 있음

## 권장 진단 순서

1. `인터페이스 환경` 또는 `어댑터 진단`에서 활성 Wi‑Fi·유선·VPN을 확인합니다.
2. `라우팅 근거`에서 현재 내부 URL을 가져와 `내부 DIRECT 측정 대상`으로 확인합니다.
3. 내부 대상이 Wi‑Fi를 선택하는지 확인합니다.
4. 외부 대상은 프록시 경로 판정 결과를 먼저 확인합니다.
5. 프록시 엔드포인트를 운영 정책상 확인할 수 있을 때만 해당 엔드포인트의 로컬 라우팅을 분석합니다.
6. 내부·외부 다운로드와 브라우저 관찰 결과를 함께 비교합니다.

## 판단 한계

- `GetBestInterfaceEx`는 현재 라우팅 테이블 기반 최적 인터페이스이며 실제 TCP 연결 성공을 보장하지 않습니다.
- Windows Filtering Platform, 보안 에이전트, 투명 프록시와 애플리케이션별 네트워크 정책은 이 결과만으로 완전히 판정할 수 없습니다.
- DNS 응답은 시간과 네트워크 정책에 따라 바뀔 수 있습니다.
- 회사 프록시 사용 시 외부 사이트의 직접 경로 분석은 실제 외부 측정 경로가 아닐 수 있습니다.
- 이 기능은 프록시 서버 내부 CPU·세션·큐·캐시·정책 상태를 확인하지 않습니다.
