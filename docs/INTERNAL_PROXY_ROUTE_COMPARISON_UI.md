# 내부 DIRECT ↔ 프록시 경로 비교 UI

`경로 비교` 탭은 사용자가 승인된 내부 DIRECT 대상과 현재 외부 대상에 적용된 프록시 지시문을 직접 입력해 Windows 로컬 인터페이스를 비교하는 화면입니다.

## 입력

### 내부 DIRECT 기준 대상

다음 중 하나를 입력합니다.

```text
https://internal.example/path/file.bin
internal.example
10.20.30.40
2001:db8::10
```

이 대상은 회사 정책상 프록시를 우회하는 승인된 내부 주소여야 합니다. 프로그램은 입력만 보고 DIRECT를 자동 증명하지 않으므로 사용자가 알고 있는 내부 기준 대상을 사용합니다.

### 프록시 지시문

다음 형식을 지원합니다.

```text
PROXY proxy-a.example:8080; DIRECT
HTTPS proxy-b.example:8443; PROXY proxy-a.example:8080
http=proxy-http.example:8080;https=proxy-connect.example:8080
SOCKS5 [2001:db8::5]:1080; DIRECT
```

현재 단계에서는 Windows 설정 또는 PAC 결과를 자동으로 텍스트 상자에 채우지 않습니다. 사용자가 현재 대상에 실제 적용된 값을 확인해 입력합니다. 자동 연동은 별도 후속 기능에서 구현합니다.

## 실행 시 수행하는 작업

버튼을 누른 경우에만 다음을 수행합니다.

1. 현재 Native WLAN 연결과 인터페이스 ID 확인
2. 내부 대상의 IP 리터럴 또는 DNS 주소 확인
3. 내부 대상의 Windows 최적 로컬 인터페이스 확인
4. 프록시 문자열 로컬 파싱
5. 각 비-DIRECT 프록시 후보의 IP 또는 DNS 주소 확인
6. 프록시 후보별 Windows 최적 로컬 인터페이스 확인
7. 현재 WLAN GUID와 프록시 경로 상관분석
8. 내부 DIRECT와 모든 프록시 후보의 전체 인터페이스 GUID 정확 비교
9. 안전한 텍스트 결과와 고정 Finding 표시

`DIRECT` 지시문에는 DNS 또는 프록시 엔드포인트 경로 조회를 수행하지 않습니다.

## 수행하지 않는 작업

```text
HTTP/HTTPS 다운로드
프록시 TCP 연결
프록시 인증
PAC/WPAD 파일 다운로드
프록시 서버 관리 API
결과 업로드
AI 또는 로컬 AI 분석
텔레메트리
자동 업데이트
```

따라서 이 탭은 속도를 측정하지 않고, 현재 PC의 첫 로컬 송출 인터페이스 선택만 비교합니다.

## 버튼 상태

경로 비교 중에는 다음을 임시로 비활성화합니다.

- 내부 다운로드 측정 시작
- 외부 다운로드 측정 시작
- 브라우저 관찰 시작
- 입력 텍스트 상자
- 새 경로 비교 시작

`경로 확인 중지`는 활성화됩니다. 비교 종료 후 기존 버튼의 활성 상태를 복원합니다.

이미 속도 측정 또는 브라우저 관찰이 진행 중이면 경로 비교를 시작하지 않습니다.

## 취소

사용자가 취소하면:

- 현재 CancellationToken 취소
- 이후 프록시 후보 조회 중단
- 완료되지 않은 후보 미조회
- 입력 원문과 예외 메시지 미표시
- 이전에 완성된 비교 결과는 자동 덮어쓰지 않음

DNS 조회가 운영체제 내부에서 진행 중이면 취소 반영까지 짧은 지연이 있을 수 있습니다.

## 표시 결과

```text
상태: Ready | Diverged | Ambiguous | Incomplete
관계: SameInterface | DifferentInterface | MultipleInterfaces | Unknown
판정 코드
전체 인터페이스 ID 정확 비교 수행 여부
내부 경로 상태·인터페이스 범주·지문
프록시 분석 상태와 후보 수
후보별 종류·범위·포트·호스트 지문
후보별 인터페이스 범주·지문·WLAN 상관 상태
프록시 파싱 경고의 구간·심각도·고정 코드
해석·한계·다음 확인
보고서 Finding 코드·심각도·제목·근거
```

프록시 파싱 Issue의 임의 원문 메시지는 화면 렌더러가 사용하지 않습니다. 구간 번호, 안전한 심각도와 검증된 고정 코드만 표시합니다.

## 개인정보 경계

입력 텍스트 상자에는 사용자가 입력한 원문이 표시되지만, 결과 영역에는 다음 원문을 복사하지 않습니다.

- 내부 대상 URL·호스트·IP
- 프록시 호스트
- PAC 원문 세그먼트
- 전체 인터페이스 GUID
- 인터페이스 이름과 설명
- SSID와 BSSID
- 예외 원문 메시지

결과에는 검증된 범주·상태·포트와 SHA-256 앞 10자의 짧은 지문만 표시합니다.

프록시 입력은 앱 메모리의 텍스트 상자에만 있고 자동 파일 저장이나 외부 전송을 하지 않습니다. 회사 밖으로 화면을 공유하기 전에는 사용자가 입력 영역이 보이지 않도록 확인해야 합니다.

## 판정 해석

### Ready

내부 DIRECT 대상과 모든 확인된 프록시 후보가 같은 Windows 인터페이스 GUID를 선택합니다.

첫 로컬 NIC가 같다는 뜻이며 이후 경로 또는 성능 동일을 의미하지 않습니다.

### Diverged

내부 DIRECT와 프록시 후보의 첫 로컬 NIC가 다릅니다.

VPN·터널·유선·무선 우선순위 또는 의도된 분할 라우팅일 수 있으므로 자동 장애로 표시하지 않습니다.

### Ambiguous

내부 주소 계열이나 프록시 fallback 후보가 둘 이상의 NIC를 선택합니다.

실제 요청 후보와 IPv4·IPv6 경로를 별도로 확인합니다.

### Incomplete

일부 후보 실패, 취소, 부분 파싱, 후보 잘림, DIRECT-only 또는 전체 GUID 미확인으로 정확 비교를 완료하지 못했습니다.

## 메모리 상태

성공적으로 결과가 생성되면 다음 값을 현재 앱 실행 동안만 유지합니다.

- 내부 DIRECT 경로 근거
- 프록시 엔드포인트 경로 분석
- 비교 결과
- 비교 Finding

앱 종료 시 사라집니다. 후속 전용 보고서 기능은 이 메모리 상태를 로컬 JSON·CSV·HTML로 저장하게 됩니다.

## 실제 검증

1. Wi-Fi만 활성화한 상태에서 내부·프록시 모두 Wireless로 나오는지 확인합니다.
2. 회사 VPN 연결 전후 프록시 후보가 Tunnel로 바뀌는지 확인합니다.
3. 유선과 Wi-Fi를 동시에 연결해 내부·프록시 우선순위를 확인합니다.
4. PAC 결과에 복수 프록시와 DIRECT fallback을 넣어 순서가 유지되는지 확인합니다.
5. IPv4·IPv6 프록시 후보가 서로 다른 NIC를 선택하면 Ambiguous인지 확인합니다.
6. 프록시 호스트 DNS 실패와 DIRECT fallback이 PartialSuccess·Incomplete로 표시되는지 확인합니다.
7. 비교 중 중지를 눌러 이후 후보 조회가 중단되는지 확인합니다.
8. 결과 영역에 실제 호스트·전체 GUID·SSID·BSSID가 표시되지 않는지 확인합니다.
9. 경로 비교 중 속도 측정·브라우저 관찰 버튼이 비활성화되는지 확인합니다.
10. 비교 종료 후 기존 버튼 상태가 복원되는지 확인합니다.
