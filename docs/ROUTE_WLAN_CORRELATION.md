# Windows 라우팅 인터페이스와 Native WLAN NIC 비교

목적지별 라우팅 근거는 Windows가 선택한 로컬 인터페이스가 현재 연결된 Native WLAN 인터페이스와 정확히 같은 장치인지 추가로 비교합니다.

단순히 인터페이스 범주가 `Wi-Fi`인지만 보면 내장 Wi-Fi와 USB Wi-Fi가 동시에 활성화된 PC에서 다른 무선 NIC를 같은 경로로 오판할 수 있습니다. 이 기능은 인터페이스 ID를 비교해 다음 상황을 구분합니다.

- 현재 연결된 Wi-Fi와 같은 NIC
- 현재 연결된 Wi-Fi와 다른 물리 Wi-Fi
- 유선 인터페이스
- VPN 또는 터널 인터페이스
- 가상 또는 기타 인터페이스
- WLAN ID 또는 단일 라우팅 인터페이스를 확인하지 못한 상태

## 비교 순서

```text
Native WLAN 현재 연결 확인
  ↓
인터페이스 ID 정규화
  ↓
GetBestInterfaceEx가 선택한 로컬 인터페이스 ID 정규화
  ↓
정확한 ID 비교
```

GUID의 중괄호와 대소문자 차이는 정규화합니다. 문자열 일부 일치, 인터페이스 이름 유사도와 임의의 첫 후보 선택은 사용하지 않습니다.

Windows 어댑터 인벤토리에서 원본 ID를 얻지 못해 만든 `local-*` 보조 ID 또는 중복 ID 충돌을 해소하기 위한 `duplicate-*` ID는 Native WLAN GUID와 정확 일치하는 근거로 사용하지 않습니다.

## 구조화 상태

| 상태 | 의미 |
|---|---|
| `Matched` | Windows 최적 라우팅 인터페이스와 현재 Native WLAN ID가 같음 |
| `DifferentInterface` | 다른 Wi-Fi·유선·VPN·기타 인터페이스가 선택됨 |
| `WlanIdentityUnavailable` | 현재 연결 WLAN의 유효한 인터페이스 ID를 확인하지 못함 |
| `RouteInterfaceUnavailable` | 경로 없음·복수 경로·인터페이스 ID 미확인으로 단일 비교 불가 |
| `NotEvaluated` | 상관분석을 아직 적용하지 않음 |

## 화면과 이력

라우팅 결과 메시지에는 다음 형식의 설명을 추가합니다.

```text
WLAN NIC 비교: Windows 최적 라우팅 인터페이스가 현재 연결된 Native WLAN 인터페이스와 일치합니다.
```

불일치 시에는 경고에도 원인을 추가합니다.

```text
현재 연결된 Wi-Fi가 아닌 유선 인터페이스 선택
현재 연결된 Native WLAN과 다른 Wi-Fi 인터페이스 선택
현재 연결된 Wi-Fi가 아닌 VPN·터널 인터페이스 선택
```

메모리 이력과 라우팅 보고서에는 상관분석이 적용된 결과를 저장합니다. 전체 GUID는 저장하지 않고 현재 WLAN ID의 SHA-256 앞 10자리 지문만 보조 값으로 사용합니다.

## 통신 경계

상관분석은 다음 로컬 정보만 추가로 읽습니다.

- Native WLAN 현재 연결 상태
- Native WLAN 인터페이스 ID
- 이미 계산한 Windows 최적 라우팅 인터페이스 ID

다음 통신은 추가하지 않습니다.

- DNS 조회
- HTTP/HTTPS 요청
- PAC/WPAD 조회
- 외부 API 호출
- 텔레메트리 또는 업로드

호스트·URL 라우팅 확인에서 발생할 수 있는 DNS는 기존과 같이 사용자가 확인 버튼을 누른 경우에만 수행합니다.

## 해석 예

### 내부 DIRECT 대상 + Matched

내부 기준 서버의 Windows 최적 인터페이스가 현재 연결된 WLAN NIC와 같습니다. 내부 HTTP 처리량을 무선 경로 진단에 사용할 수 있는 근거가 강화됩니다.

다만 AP 이후 컨트롤러·터널·유선 서버 구간은 계속 포함됩니다.

### 내부 DIRECT 대상 + 다른 Wi-Fi

내장 Wi-Fi와 USB Wi-Fi가 동시에 활성화됐을 가능성이 있습니다. WLAN 상태와 다운로드 처리량이 서로 다른 NIC에서 측정될 수 있으므로 사용하지 않는 Wi-Fi를 비활성화하거나 Windows 라우팅을 확인합니다.

### 내부 DIRECT 대상 + 유선

다운로드 요청은 유선을 선택하지만 화면의 WLAN 상태는 Wi-Fi에서 읽는 불일치입니다. 이 결과로 Wi-Fi 속도를 판단하지 않습니다.

### 프록시 엔드포인트 + VPN

PC에서 회사 프록시까지의 로컬 경로가 VPN 또는 보안 터널을 선택합니다. 외부 측정 결과에는 Wi-Fi 물리 구간과 VPN·프록시 경로가 함께 영향을 줄 수 있습니다.

### 외부 사이트 참고 경로 + Matched

회사 프록시 환경에서는 외부 사이트 주소의 직접 경로가 Wi-Fi와 일치해도 실제 HTTP 연결이 같은 경로라는 뜻은 아닙니다. 실제 로컬 연결 대상은 프록시 엔드포인트일 수 있습니다.

## 판단 한계

- 인터페이스 ID 일치는 로컬 NIC 대응 근거이며 실제 TCP 연결 성공을 보장하지 않습니다.
- 프록시·VPN·Windows Filtering Platform·투명 프록시 정책은 ID 비교만으로 완전히 판정할 수 없습니다.
- IPv4와 IPv6가 서로 다른 인터페이스를 선택하면 단일 인터페이스 비교를 수행하지 않습니다.
- Native WLAN ID 조회가 제한된 환경에서는 범주·상태·라우팅 근거만 표시하고 정확 일치로 단정하지 않습니다.
